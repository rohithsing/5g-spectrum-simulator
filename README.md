# Intelligent Spectrum Allocation for Efficient 5G/6G Networks

A reinforcement-learning dynamic spectrum allocator, benchmarked against the
schedulers actually deployed in LTE/NR base stations today, inside a 3GPP-grounded
simulator.

The project's claim is narrow and testable: **given exactly the same information a
real gNB scheduler has, a learned allocator serves more users inside their QoS
contracts and causes less harmful interference to the incumbent than Round-Robin,
Proportional Fair, Max-C/I, M-LWDF or EXP/PF.**

---

## Why a simulator

No research group has write access to a live spectrum allocation system, and a
scheduler cannot be evaluated from logs alone: you have to be able to replay the
same radio conditions and ask "what if a different decision had been made?".
Everything here is therefore generated by a simulator whose parameters are
individually traceable to 3GPP specifications — see `spectrum/config.py`,
`PARAMETER_PROVENANCE`, and `tests/test_physics.py`, which checks the physics
against the specs it claims to follow.

No external dataset is used, and none is needed.

---

## The fairness problem, and how it is solved

A learned allocator will beat anything if you quietly give it information the
baselines do not have. The single most common way this happens in spectrum-sharing
papers is letting the agent see the incumbent's true occupancy while the baselines
only get a noisy detector output.

This project forbids that structurally:

* Every allocator receives one `Observation` object (`spectrum/env.py`). Its fields
  are buffer status reports, head-of-line delays, 5QI parameters, **aged and
  quantised** CQI reports, and the output of **one shared energy detector**
  operating at a fixed `P_d = 0.85`, `P_fa = 0.12`.
* The incumbent's true state is not a field of `Observation`. It is consumed only
  inside the physics and the collision accounting.
* `tests/test_information_parity.py` asserts this mechanically, including a replay
  test: each allocator is fed recorded observations with **no environment attached**
  and must reproduce its decisions exactly. If it read anything else, the test fails.

Baselines are also kept strong rather than strawmen. Each one is PRB-granular (same
action space as the learned policy), buffer-aware (it stops allocating to a UE whose
queue is covered, so it wastes nothing artificially), and uses the standard DSA rule
of muting a subband the detector flags as busy.

## What the system actually is

Two learned components behind the same observation interface:

**1. Incumbent-occupancy predictor** (`spectrum/predictor.py`)
A GRU filter over the sensing stream. An energy detector is memoryless, but
incumbent bursts last tens of slots — so the detector looks at the same hidden
state many times in a row and a classical radio throws all but the last look away.
The GRU is given neither the Markov transition matrix nor the detector calibration
and infers both from data.

**2. Scheduling policy** (`spectrum/policy.py`)
An attention encoder over UEs — permutation-equivariant, so one set of weights
works for a 20-UE cell and an 80-UE cell. Each UE emits a priority score and a
channel sensitivity; the logit for assigning UE *u* to RBG *k* is
`scale · (score_u + gain_u · z_uk)`. RBGs are assigned sequentially and a UE leaves
the candidate set once its queue is covered, so over-allocation is structurally
impossible. Each RBG may also be muted, and that decision is driven by the
predictor's output.

Trained by **behaviour cloning, then PPO** (`spectrum/bc.py`, `spectrum/ppo.py`).
The warm start matters for the integrity of the result: PPO begins at parity with
the strongest non-RL scheduler rather than far below it, so the reported gain is
unambiguously what reinforcement learning *added*. The pre-RL checkpoint is kept
and reported as an ablation.

The teacher is M-LWDF driven by the learned occupancy estimate, not plain M-LWDF.
That detail is load-bearing: plain M-LWDF mutes exactly when the hard sensing bit
is set, so a student cloning it learns the bit predicts the teacher perfectly and
ignores `p_busy` — inheriting the classical detector's collision rate despite
having a better estimate in its own input. Switching the teacher cut the clone's
collision rate by 2.4–3.6× (peak: 11.5 % → 3.2 %).

## Results

Run `python evaluate.py`; it writes `results/benchmark_report.md` with full tables.

### Incumbent-occupancy estimation

Held-out traces, averaged over all four congestion regimes:

| Estimator | Accuracy | Precision | Recall | F1 | AUC | Missed detections | False alarms |
|---|---|---|---|---|---|---|---|
| Energy detector (classical) | 0.871 | 0.722 | 0.851 | 0.774 | 0.865 | 14.9 % | 12.1 % |
| **Learned GRU (proposed)** | **0.976** | **0.961** | **0.956** | **0.959** | **0.995** | **4.4 %** | **1.7 %** |
| Bayes-optimal (upper bound) | 0.978 | 0.968 | 0.957 | 0.963 | 0.996 | 4.3 % | 1.6 % |

The Bayes-optimal row is the HMM forward filter *given the true model parameters*.
It is not deployable — it exists to show how much of the achievable gain the learned
filter captures, which is roughly 98 %.

Both error types matter and they pull in opposite directions for a classical
detector — lowering the threshold trades false alarms for missed detections and
vice versa. A missed detection is harmful interference to the incumbent; a false
alarm is spectrum thrown away. Because the learned filter integrates evidence over
a burst instead of moving a threshold, it reduces missed detections by **3.4×** and
false alarms by **7.0×** *simultaneously*, which no choice of operating point on
the classical detector's ROC curve can do.

### System KPIs

See `results/benchmark_report.md` and `results/plots/`. Every comparison is paired —
each allocator faces an identical UE drop, traffic realisation and incumbent
trajectory — and is reported with a bootstrap 95 % CI, a paired Wilcoxon
signed-rank p-value and Cliff's delta.

## Layout

```
spectrum/
  config.py       3GPP-traceable parameters, 5QI traffic classes, congestion regimes
  channel.py      UMa NLOS path loss, time+frequency correlated fading, CQI/MCS, HARQ
  traffic.py      Per-UE bursty arrivals, packet queues, delay budgets, expiry
  incumbent.py    Semi-Markov occupancy + energy detector at a fixed (Pd, Pfa)
  env.py          Slot-level environment; defines the Observation contract
  metrics.py      Every KPI definition, shared by reward, benchmark and dashboard
  baselines.py    Round-Robin, Proportional Fair, Max-C/I, M-LWDF, EXP/PF
  predictor.py    Energy detector / Bayes filter / learned GRU + scoring
  policy.py       Attention policy network and the sequential action decoder
  bc.py           Behaviour cloning from M-LWDF
  ppo.py          PPO trainer
  agent.py        The proposed allocator, plus ablation wrappers
  runner.py       Episode runner shared by training, evaluation and the dashboard
train.py          Stage 1 predictor -> Stage 2 BC + PPO   (~35 min, CPU)
evaluate.py       Paired benchmark, statistics, plots, report
app.py            Streamlit dashboard
tests/            Physics, allocator contract, and information-parity tests
```

```bash
pip install -r requirements.txt

python train.py                  # ~35 min on CPU; --quick for a 4 min smoke run
python evaluate.py               # paired benchmark -> results/
streamlit run app.py             # interactive comparison

python -m pytest tests/ -q       # 50 tests: physics, contracts, information parity
```

| File | What it is |

## Simulator details

**Radio.** 100 MHz carrier at 3.5 GHz (band n78), 30 kHz subcarrier spacing,
273 PRBs grouped into 18 RBGs, 0.5 ms slots, 46 dBm EIRP, 350 m cell radius.
The resulting SINR distribution spans −3 dB (5th percentile) to 32 dB (95th),
median 11.6 dB — a textbook dense-urban macro deployment.

**Propagation.** TR 38.901 UMa NLOS path loss, 5 dB log-normal shadowing.
Small-scale fading is correlated in time (first-order Gauss-Markov with a
Jakes coefficient derived from each UE's Doppler) and in frequency (exponential
decay across RBGs). Both matter: time correlation is what makes the channel
partly predictable, frequency selectivity is what makes *which* RBG goes to
*which* UE a real decision.

**Link adaptation.** SINR → CQI via TS 38.214 table 2 at a 10 % BLER target.
The scheduler chooses its MCS from a CQI report that is 2 slots old and
quantised, so an optimistic report produces a genuine decode failure. HARQ
retransmissions accumulate chase-combining gain.

**Traffic.** Four 5QI bearers from TS 23.501 table 5.7.4-1 — URLLC (5QI 82,
10 ms budget), VoIP (5QI 1), live video (5QI 2) and best effort (5QI 9) —
with log-normal payloads, bursty arrivals, and packets that are **dropped**
when their delay budget expires.

**Incumbent sharing.** Two-state semi-Markov occupancy per subband with
geometric sojourn times, duty cycle set by the congestion regime (12 % → 46 %).
Transmitting on an occupied subband is a harmful-interference event and is
counted as such.

## Honest limitations

* Single cell. Inter-cell interference is a static floor, not a second scheduler
  reacting to this one. Multi-cell coordination is the obvious next step.
* Single antenna port. No MIMO, no beamforming, no spatial multiplexing.
* The incumbent is a two-state Markov process. Real radar and satellite incumbents
  have structured duty cycles that would be *easier* to predict, so the predictor
  result here is, if anything, conservative.
* The Bayes-optimal reference is only optimal for this incumbent model.
* Results are simulator-internal. They demonstrate that the learned policy
  dominates classical schedulers under these dynamics; they are not a measurement
  of a deployed network.
